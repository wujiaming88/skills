# 意图与提示词

把需求翻译成一次高质量请求的方法。参数取值与校验见 [api.md](api.md)，可运行命令见 [examples.md](examples.md)。文中 slug 与标签行都写在 prompt 内部，不是接口字段。

## 判定意图

| 输入 | 判定 |
|---|---|
| 没有图片 | `generate` |
| 有图片，只用其风格、构图、氛围或主体外观作参考，产出新画面 | `generate`，图片是参考而非编辑对象 |
| 有图片，要求保留其整体或局部（换背景、改物体、换材质、改文字、换光线） | `edit` |
| 有图片，要求在指定位置改动或跨图移动主体 | `edit`，用坐标或标注图定位 |
| 单张设计稿要拆成可编辑素材 | `layers` |

- 分不清时按 `generate` 处理并一句话说明。误判成 `edit` 会让模型强行保留本不该保留的内容。
- “白底”“去背景”“抠图”不等于 `transparent`。透明只在输入图已有透明通道时可用，其他抠图处理须作为独立流程说明。
- 图层拆分与上面的判定相互独立，只由产物形态决定。

## 提示词结构

标签行按需取用，不必写全：

```text
Use case: <上文 slug>
Primary request: <用户原始需求>
Scene/backdrop: <场景与环境>
Subject: <主体>
Style/medium: <照片/插画/3D>
Composition/framing: <构图、视角、比例>
Lighting/mood: <光线与氛围>
Color palette: <配色>
Materials/textures: <材质与纹理>
Text (verbatim): "<原样文字>"
Constraints: <必须保留>
Avoid: <必须避免>
```

- 按“场景 → 主体 → 细节 → 约束”组织；复杂需求用短标签行，不用一段长文。
- 参考图用“图1/图2”指代，并在 `Primary request` 里写清每张图提供什么。
- Seedream 没有 `negative_prompt`，负向要求写进 `Avoid` 行；也没有 mask、seed、quality、strength 字段。
- `optimize_prompt_options` 是服务端优化档位，不假设它会补全或保留关键约束；不变量显式写进 `Constraints` 与 `Avoid`。
- 建议长度：中文 ≤300 字、英文 ≤600 词（非硬性截断）。
- Pro 支持中文、英文、俄语、阿拉伯语、菲律宾语、泰语、土耳其语、韩语、马来语、西班牙语、葡萄牙语、印尼语、法语、德语、越南语和日语文字生成。文字仍须实际检查，不承诺排版或拼写绝对准确。

## 具体度策略

- 需求已经具体 → 只做结构化归一，不加创意要求。
- 需求笼统 → 才补材质、光线、构图、用途等能实质提升结果的细节。
- 可以补：构图与取景、用途与完成度、版面指引、与需求一致的场景具体化。
- 不可以补：未被暗示的人物或道具、品牌色/标语/情节、没有版面依据的左右侧位置。
- 编辑类需求每轮重述不变量，一次只改一个变量。

## 接续创作与指代

用户说“根据刚才那张”“继续做”“延展上一版”“把上一张改成”时，先解析指代再动手：

- 只把用户明确指向、或能按最近轮次与主体匹配可靠判断的那张图作为输入，不把上一轮所有图都传入。
- 被指向的图是主体、版式基础或一致性载体时按 `edit` 处理；若它只提供灵感、不需要保持一致，说明“仅作风格参考”后按 `generate` 处理。
- 指代不清时先问一句是哪张，不猜。

## 核心资产与一致性

系列、套图、多平台适配和品牌延展任务，先确定一个一致性载体：

- 先生成一张干净、可复用的主图，确认后即为核心资产；后续所有物料都以它为 `edit` 的第一张输入图，并在 prompt 中写清“保持图1的……不变”。
- 用户上传的 logo、产品图、包装、IP、主 KV 默认就是核心资产，除非用户明确说“只参考风格”。
- 禁止只用文字描述重新生成相似版本；文字描述无法保证系列一致。
- 同一时刻优先维护一个核心资产。多张参考图时用图1、图2分别标明作用。

## 事实与文案边界

事实文字必须来自用户或已确认资产，并原样给出：

- 品牌、主标题、日期、数字、价格、地点、专名、型号、活动名称逐字取用，用对应语言的引号框定（中文用中文引号，英文用英文引号，中英混排分别框定）。
- 价格、日期、折扣、销量、功效百分比、排名、评分、认证编号和监管声明只能来自用户提供或已确认资产；未提供时不得编造。

非事实文案可以交给模型扩写，但要给出明确的开放引导：

- 需要副标题、栏目标题、标签、卖点表达、规则摘要或行动引导而用户未提供时，在 prompt 中写入：“根据画面自动扩写合适的文案，围绕「主题」面向「受众」采用「语气」表达，可发展……，并沿……自然融入主视觉。”
- 文案角色已经完整，或用户要求少字、无字、纯视觉时，删除该句。

红线：

- 禁止 `XX`、`某某`、`标题文案`、`待补充文字`、`相关说明`、`若干文字`、`占位符` 这类让模型自由补字的写法。
- 平台名与用途说明（如“小红书封面”“抖音风”“公众号首图”）不写进 prompt，转译为视觉风格、构图和信息密度。
- 不直接使用第三方品牌、影视作品、受保护 IP 或在世艺术家姓名作为风格锚点，转成通用风格语言。
- 平面设计任务不描述画面之外的展示背景，除非目标就是 mockup 或空间展示。
- Seedream 没有 `negative_prompt`，所有“不要……”改写成正向视觉目标。

构图原型、阅读顺序和量化约束见 [composition.md](composition.md)；风格、色彩与完成度收尾见 [aesthetics.md](aesthetics.md)。

## 坐标和标注图

坐标不是独立JSON字段，直接嵌入prompt：

```text
将图1<bbox>179 283 796 986</bbox>的主体放到图2<bbox>118 331 933 871</bbox>位置。
把图1<point>520 460</point>位置的杯子换成花瓶。
将图1<bbox>120 180 640 760</bbox>区域内的左侧人物换成机器人；图1<bbox>700 120 920 360</bbox>保持不变。
```

输入坐标范围 **0–999**，原点为图片左上角。点为 `x y`，框为 `left top right bottom`。按实际显示图片区域宽高计算 `round(pixel / dimension * 1000)`，裁剪到0–999；不把界面边框、留白、画布偏移或缩放算进图片。例：宽1000、高500的图片内点(250,125)→`<point>250 250</point>`；右下边缘→999,999。框应有正宽高，极小框四舍五入后坍缩时重新选范围。

这与响应图层的0–1000归一化坐标不同。框内有多个物体时，仍需文字明确对象。没有准确定位信息时，不伪造“精确坐标”；可通过实际图片检查或自然语言描述确定目标。

也可输入已标记图片并写：“根据手绘标记，在左下区域添加杂志，在右侧区域添加杯碟咖啡。移除全部标记线条，保持其他构图不变，使新增物体自然融入场景。”

## 参数与产物检查

- 默认2K/standard用于最终交付；快速草案可选fast，尺寸满足用途。精确尺寸用合法WIDTHxHEIGHT，普通模式不传auto。
- 多个候选逐个独立调用，每次一张，保持用户要求数量；不能伪装成n参数或组图能力。
- 不把“白底”“去背景”自动映射为transparent。透明输出仅适用于带透明通道参考图的编辑；其他抠图处理须作为独立流程说明。
- 交付前检查主体和身份、文字原样、构图、未修改部分、透明通道。不符合时说明差异，在授权的迭代范围内修订prompt，不无限重试。
