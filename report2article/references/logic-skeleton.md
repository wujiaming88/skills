# 文章结构与章节设计

目标不是把报告标题换一遍，而是建立符合读者认知顺序的主线。先确定文章要回答的核心问题，再决定章节；不要先按对象机械切块。

## 选择一条主线

| 主线 | 适用内容 | 读者路径 |
|---|---|---|
| 时间线 | 事件或技术持续演变 | 起点 → 关键变化 → 当前状态 |
| 问题递进 | 一个主题包含多个深度层次 | 现象 → 原因 → 机制 → 影响 |
| 对比 | 多个明确可比的对象或方案 | 比什么 → 各自表现 → 报告结论 |
| 因果链 | 报告明确给出原因和结果 | 原因 → 作用过程 → 结果与边界 |
| 总分总 | 对象多、信息密度高 | 全局导航 → 分主题展开 → 要点收束 |

只选一条作为主线，其他结构可局部辅助。没有充分证据时，不要为了制造戏剧性套用“冲突”“战争”或“逆转”叙事。

## 推荐的阅读节奏

1. **导语**：用报告中最重要的事实、变化或结论说明本文讲什么。通常 1–3 段，避免从通用行业背景起笔。
2. **必要背景**：只放理解后文必需的信息；背景很多时拆入对应章节，不在开头集中堆砌。
3. **主体章节**：按照选定主线推进，每章回答一个读者问题。
4. **收束**：回到报告明确表达的结论、影响或未决问题。报告没有结论时，回顾已知事实即可。

这是一种阅读节奏，不是必须出现四个同名章节的模板。

## 章节划分规则

- 一个二级章节只承担一个核心问题；标题读完就能预期本节内容。
- 信息属于同一问题时合并，不因对象不同而强行分章。
- 同一对象承担不同论证作用时，可以出现在多个章节，但不要重复同一信息。
- 只有一小段内容的章节通常应并入相邻章节；信息显著过载的章节应按读者问题继续拆分。
- 章节长短由信息量决定，不追求整齐；连续多个极短章节会造成“目录感”，应优先合并。
- 同级章节保持相近的抽象层级和标题句式。

## 关系表达边界

时间先后、因果、竞争、趋势和对比只能在报告**明确表达**或由原始数据直接呈现时写成结论。仅仅把两段内容放在一起，不等于报告证明了它们有关联。

- 可以写：“报告分别讨论了 A 与 B，下面依次看两条路径。”
- 只有报告明确支持时才写：“A 导致 B”“A 优于 B”“行业正在转向 C”。
- 报告未明确关系时，用章节位置完成组织，不要在标题、过渡或结尾中补出关系判断。

## 重组方法

- **打散报告模板**：把“对象 A：动态/数据/链接/判断 → 对象 B：……”改为按读者问题组织，但每条原子信息都要有落点。
- **融合信息形态**：事实、数据和来源可以写成自然段或表格，不保留“关键数据”“影响判断”等报告标签。
- **先结论后证据**：只有报告已有结论时，才可把结论前置；紧接着给出对应事实、数据和来源。
- **导航式过渡**：过渡只说明接下来读什么，不携带新的事实、因果或评价。

速查表只能帮助导航，不能替代承载完整信息的正文。
