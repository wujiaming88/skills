# 文章配图规范

配图的目标是降低认知负担、解释复杂关系或帮助快速比较，不是让页面“看起来丰富”。没有明确阅读收益时，宁可不配图。

## 先判断是否需要图

适合配图的信号：

- 多组精确数据需要比较或观察趋势；
- 多个时间节点需要展示演变；
- 流程、因果链、系统层级或组件关系仅靠文字难以理解；
- 多个方案需要按相同维度快速扫描；
- 抽象概念需要一张明确标注的示意图帮助建立心智模型。

不适合配图的情况：只有一两个数字、图与正文表达完全重复、数据口径不完整、概念关系来自编辑推测，或只是为了装饰。

## 选择合适的形式

| 信息关系 | 首选形式 | 注意 |
|---|---|---|
| 精确数值比较 | 柱状图、点图或正文表格 | 从零起点是否必要取决于图形；不得夸大差异 |
| 连续时间变化 | 折线图或时间线 | 标明时间范围、缺失值和事件来源 |
| 步骤与状态变化 | 流程图 | 区分先后、分支与可选步骤 |
| 系统组成与依赖 | 架构图或层级图 | 只画原报告明确支持的节点和关系 |
| 多对象多维比较 | Markdown 表格或对比矩阵 | 文字较长时不要强做图片 |
| 抽象主题或开篇氛围 | 概念示意图 | 必须标明“示意图”；不制造数据或事实感 |

能用可访问的正文表格说清楚时，优先表格而不是截图式图片。

## 素材优先级

1. **复用原报告图片**：保留原图来源、标题、时间和必要注释。
2. **基于原报告数据重绘**：只使用清单中的 F/D/L 编号，保持单位、口径和时间范围。
3. **制作结构化示意图**：节点与关系必须来自报告，图注明确写“示意图”。
4. **概念插图**：只在帮助定位主题时使用，不承载事实证据。

不得编造缺失数据、补齐趋势线、虚构比例或把不完整样本画成全局结论。原报告数据不足以支撑图表时，改用文字或配图方案说明缺口。

## 位置与数量

- 图片放在首次需要它的段落之后，不与证据相隔多个章节。
- 一幅图只承担一个主要阅读任务；图中重点与正文重点一致。
- 不设“每千字一图”之类硬指标。常见长文 2–4 幅通常足够，但由内容决定。
- 同一信息不要同时用大段正文、表格和图片重复三遍；正文解释图中最重要的发现即可。

## 每幅图的交付要素

实际图片必须同时具备：

- **图题**：说明图展示什么；
- **图注**：解释口径、时间范围、缩写和“示意图”属性；
- **来源**：原报告图片或支撑该图的链接；
- **替代文本**：用一句到三句描述图的主要信息，不能只写“图片”；
- **文件名**：使用稳定、可读的英文小写名称，如 `agent-platform-timeline.png`。

数据图还要检查坐标轴、单位、图例、颜色含义和数据标签。颜色不是唯一区分手段，避免仅靠红绿表达结论。

## 生成与授权边界

只有用户明确要求产出实际图片，并且当前环境提供可用的制图或图像生成能力时，才创建图片文件。生成图片应放在文章同级的 `<文章名>-assets/` 目录，并在 Markdown 中使用可解析的相对路径。

如果用户未要求实际生成、工具不可用或数据不足，输出配图方案，不假装图片已经生成。每个方案使用以下格式：

```markdown
> 配图方案
> - 位置：章节与段落之后
> - 类型：时间线 / 图表 / 流程图 / 架构图 / 示意图
> - 阅读目的：这幅图替读者解决什么问题
> - 内容：节点、数据、标签与对应 F/D/L 编号
> - 图题与图注：拟用文案
> - 来源：原报告位置或链接
> - 替代文本：拟用 alt 文本
```

调用图像生成能力时，视觉风格可以编辑，事实边界不能编辑。生成后必须查看实际图片，核对文字、数字、标注和构图；未检查的图片不能交付。
