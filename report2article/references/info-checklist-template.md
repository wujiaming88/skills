# 原子信息与双向校验模板

## 1. 建立基线

每条独立信息有稳定编号，不逐句复制，不把重复措辞算新信息：

```markdown
## 对象 O
- [ ] O01：对象全名｜允许简称｜适用范围｜母稿位置
## 共同限定 C（可选，不另计事实）
- C01：共同期间/口径/归因/限定的完整定义｜适用条目｜母稿位置
## 事实 F
- [ ] F01：本条独立事实｜@O01｜@C01｜@L01｜母稿位置
## 数据 D
- [ ] D01：本条数值及单位｜@O01｜@C01｜@L01｜母稿位置
## 判断 J
- [ ] J01：本条判断原义及强弱｜@O01｜@C01｜@L01｜母稿位置
## 来源与链接 L
- [ ] L01：来源名称｜URL｜逐项支撑F/D/J编号及支撑边界｜母稿位置
```

表中引用只演示写法，只引用实际适用的本清单定义；本条特有限定直接写在本条，不强行装入共同限定，也不因未单列某字段而省略信息。共同字段由直接引用承载后，不再在F/D/J逐条全文重抄。

记录冻结母稿路径、版本和公开边界、首次原始计数。同一URL只计一个L但记录所有支撑关系；不同时间、范围、口径、归因分开编号。独立二次提取用自己的编号和粒度，不看首次清单或成稿。

### 清单内单处定义与短引用

在每份清单内部，对反复适用的对象、共同限定和来源只定义一次；F/D/J各写自身独立信息及适用引用，不重抄其他类别全文。无重复信息无需另建公共区；公共定义仍在该清单内，不成为第三套清单，也不额外计作事实。两份独立清单不能共享提取内容或公共定义。

使用稳定、唯一、可解析的短引用，例如 `@O01`（对象）、`@C01`（本清单共同限定）、`@L01`（来源）；一次直接定位到本清单完整定义，定义中不再转引其他定义。其他明确且同样可解析的编号写法也可用，不强制改写既有编号。F/D/J引用其他类别的信息时，直接指明实际承载的条目及字段并打开核对；普通相关编号只作回查索引，不以关系链传递推定本条已记录语义。悬空、循环、深链、跨清单引用或含糊简称须先展开修正；来源反列支撑编号是关系索引，不是语义继承链。

例如（仅为格式样例，不是可补入母稿的事实）：

```markdown
O01：甲公司
C01：报告期内；据甲公司披露；计划，非实际交付；母稿§2第1段
L01：甲公司公告｜https://example.invalid/notice｜直接支撑D01，不支持实际交付结论
D01：@O01；计划交付上限100台；@C01；@L01
```

展开每条及其直接引用，须可还原适用的主体、期间、单位、统计口径、分母/样本、归因、限定、判断强弱、母稿定位与来源支撑。金额上限、计划/实际、未确认/不存在及来源直接/间接支撑不能被全局免责声明吞掉；“非新法”不能缩成“非法”。不同主张即使同URL也逐项保留支持或不能支持的边界，不补造母稿未说明的未披露字段。不设清单字数或条目硬上限；引用能解析仅证明可定位，不证明等义。

## 2. 记录去向及语义映射

在现有清单/`article-traceability.md`记录去向、处理理由与核对状态；traceability只做映射，不生成第三套完整清单。先记录双方清单路径及冻结版本、文章路径及版本，位置均相对该版本；重复标题须加章节路径，正文用段落/句序或表格行列定位，必要时补短语消歧，不能只写对象名或“见正文”。

### 等义项紧凑行

等义且无差异项短记“双方编号｜母稿准确定位/必要消歧｜准确文章落点｜状态”，不整段重写双方原文。以下为定位格式样例，不是可直接宣布已核对的内容：

| 首次编号 | 二次编号 | 母稿准确定位 / 必要消歧 | 内容去向 / 准确文章落点 | 状态 |
|---|---|---|---|---|
| F01 | F02、F03 | §2第1段第2句 | 正文·核心事实：§会话第2段第1—2句 | 等义 |
| D01、D02 | D04 | §2表1第2行数值/口径列 | 正文·精确比较：§容量表1第2行及脚注a | 等义 |
| J01 | J02 | §3第2段第1句 | 正文·必要边界：§限制第1段第2句（紧邻主张） | 等义 |
| L01 | L01 | §来源第1项及其引用处 | 公开来源·追溯：#source-1及正文引用处 | 待核 |

内容去向/处理理由可用上表这类自明短标记，或在映射内单处定义标记后直接引用；它们不承载原子信息语义。L项只有逐项确认唯一URL及全部支撑关系的落点后才能标等义，必要时增列准确引用处。引用已有映射时直接指向实际行或锚点，不串联多层映射；双方编号只是对应索引，不能反向补足任一原清单缺失的语义。

实质信息只能映射正文或公开补充材料；仅生产过程可映射审计，写明为何不影响读者判断。抓取过程与由其形成的证据缺口分开处理。不能因“非主线”改成内部，关键限制不能只放附录。对分类有争议先保持公开，回母稿核验。

允许一对多、多对一，不强迫同编号、同类别粒度、同总数；逐项打开两侧条目和直接引用，确认主体、期间、单位、分母、样本、限定、来源、归因与强弱，不能只写“粒度不同”。普通一对多、多对一或跨类别等义对应，经逐项核实两侧完整承载且定位无歧义，仍用紧凑行；不因对应形态本身要求详写，也不能因母稿或文章已写就虚称原清单已记。

### 仅真实差异详记

仅在真实漏项、跨类别复杂拆合（紧凑行不足以辨明各项承载）、来源争议或判断变化时，追加差异记录；主表状态直接引用差异编号，不把详记变成所有行的必填长列。无法确认等义的条目先标待核/阻断，回母稿查明，不强行压成等义。

```markdown
X01｜类型：真实漏项/跨类别复杂拆合/来源争议/判断变化｜涉及：首次编号 ↔ 二次编号
- 双方实际承载：两侧准确条目/字段及直接定义位置；只摘必要差异，不抄两份整条。
- 缺失或差异：缺哪项、如何拆合、来源支持分歧或判断变化在哪里。
- 母稿依据：准确位置及必要证据短摘；未争议的共同条件和证据直接引用已有定义/证据位置。
- 处理结果：原清单补漏编号或协调依据、文章修订准确落点、复验状态；未解决则阻断。
```

原计数与补漏区保留，不能计数齐平或把漏项称为跨类映射来放行；无源增写须回母稿纠正，不能为协调而保留。缩短的是重复记录，不是逐项语义核对，也不是必要差异证据。

## 3. 正向覆盖

逐项核对两份清单的独立信息：对象名称范围不错配；F限定完整；D数值单位日期口径一致；J原义强弱归因一致；L保留唯一链接与支撑关系。实质信息公开可访问，生产过程在审计有合理落点。对象名出现、总数相同、链接集合相同均不能替代语义覆盖。

## 4. 全文反向溯源

从头到尾逐段反查公开内容，包括标题、导语、正文、过渡、结尾、图表、图注、附录。每项事实、数字、关系和判断回到母稿与编号；去重不丢不同限定，概念图不制造事实感。无来源内容删除或列在独立编辑建议，不留成稿；研究缺口退母稿，不能编辑补事实。

## 5. 独立二次派生与补漏

长文执行长文协议，保留两份原始清单和计数。任一方漏项，在原文件补漏区追加新编号及证据，补公开内容和映射，不覆盖原计数；等义拆分记录一对多或多对一依据，不重写清单凑数。无法确认是否重复按独立信息保留，差异未解不得PASS。不生成第三/第四套完整基线。

## 6. 交付口径

在独立交付说明报告“信息校验：O个对象 / F条事实 / D个数据点 / J条判断 / L个唯一链接，全部可追溯”，不写入文章首尾。采用首次声明粒度及有依据补漏，审计保留双方原计数和差异，不冒称原清单同数，某类0如实写0。仅在独立提取完成、差异全解释、实质信息公开全覆盖、全文反向溯源及阅读复验通过后使用此结论。

完成标记和父级审计的汇总记录冻结版本、读取/验收范围、计数、未销账数、状态及尚存阻断项；共同条件或证据直接指向实际清单定义、映射行或差异记录，不再全文重抄。新发现的问题及必要证据写入对应差异记录，汇总只引用落点。此短记不减少编辑者和父级按长文协议各自完整读取获准母稿、两份清单、映射和文章全文，逐项正向覆盖与全文反向溯源；不能只看完成标记或差异摘要。仍须执行`reading-review.md`，修订后复验受影响映射，最终验收覆盖完整新版。
